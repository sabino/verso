# Lifecycle audit closure

This records the implementation and verification of the 13 findings originally left open in [State machines and interaction contracts](STATE-MACHINES.md), plus the explicit gaps in its 97-group inventory. The closure work is based on `ad301b5`; the inventory keeps its original groups so the decisions remain traceable.

All 13 original findings have concrete changes. “Implemented” below means the transition, guard, recovery path or ownership rule exists in source, with the identified tests or harness. It does not mean every combination of states has been proved correct. Executed domain tests, hosted browser scenarios and deployment requirements are kept separate.

## Compatibility and deployment

- Estate and actor save versions and stored record shapes are unchanged. `reconcile-worker` and `retry-worker` are additive authority commands; recovery/pause fields are optional presentation data. Older frames remain readable. The world-node rollout remains pending. The [deployment workflow](WORLD-NODE-CI.md#one-time-operator-setup) requires a fresh private data/signing-identity backup, current image/configuration capture and its non-secret dispatch reference; no current backup reference is recorded here. Hosted recovery needs the updated server as well as the browser; absent readiness displays an update explanation and disabled controls, without optimistic spending.
- Supply quest `outcome: 'withdrawn'` is optional and validated. It retains `complete: false`; older readers may display an inert unfinished row, but cannot count withdrawal as paid service. Existing saves that omit the field remain valid.
- Personal history remains bounded at 128 without eviction. Existing recorded lives remain revisitable; admitting an unrecorded life at capacity is rejected visibly. This preserves existing identities and rewards instead of silently making room.
- Procedural version-1 saves keep their existing serialization rules. `Crossing.next()` now returns `Crossing | null`; callers explicitly handle an illegal transition. The current in-memory run is preserved if storage cannot accept a newer snapshot.
- Room durability is an optional welcome/status extension. New authorities apply the local-write admission policy; older clients can still understand their existing protocol. Credentials and optional replicas have separate failure status from local durable state. No wallet entitlement is inferred from a game save.
- Without Web Locks, `unsupported` deliberately permits single-tab play and saving with a visible warning. It does **not** promise exclusion across simultaneous tabs.
- Pagehide cannot force the browser to finish asynchronous signing or storage; recovery starts from the last completed checkpoint. The closing admission gate prevents newly accepted gameplay writes after final capture begins.
- Waiting service-worker updates and native install prompts remain user/browser-owned. No forced `skipWaiting`, surprise life reload or automatic microphone authorization is introduced.
