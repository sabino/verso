# State machines and interaction contracts

This is the 97-group runtime state inventory for Verso, originally audited from `e9e96fe` and updated after the lifecycle closure work based on `ad301b5`. The original findings, implemented decisions and executed evidence are tracked in [Lifecycle closure](LIFECYCLE-CLOSURE.md). It covers the main life, both earlier playable routes, browser input and presentation, shared authority, persistence, voice, and optional commerce/companion services. It is a source-backed map of owners and transitions, not a claim that every interleaving has been played or formally verified. Build/deployment job graphs and dependency internals are outside this runtime scope.

**E** means an explicit phase/status union. **I** means state encoded in optional records, booleans, collection membership, counters or clocks. **H** combines explicit states with dependent fields. **D** is a derived view of another owner's state. A row may group related but independent lifecycles; repeated boundary references do not represent additional machines. In particular, an enum describing an object's kind, a deterministic generator and an interpolation curve are not automatically state machines.

Source links name stable modules; symbols and field names identify the relevant implementation. Test links indicate coverage of that area, not proof of every transition in the row. The closure record distinguishes executed domain tests, prepared browser scenarios and environment-dependent validation.

Preserve these contracts during extraction:

- Save numbers, record shapes, world-generation versions, wire messages, request fingerprints and receipt identities remain compatible unless an explicit migration is supplied. A new UI selector must not become a second saved truth.
- Awareness and occupied body differ. Possessions, cooldowns, action debt, body/floor bindings and once-only effects must survive the transitions their owners currently preserve.
- Personal inventory, field bank, estate storage, reserved ingredients and physical worker cargo are separate containers. Similar item names do not authorize transfer or conversion.
- Finite-source and reward receipts prevent replay. Bounded ledgers that refuse new work when full must not silently evict protection. Presentation caches may evict; durable history generally may not.
- Local time, active simulation time, authoritative time and real service deadlines differ. Pausing a client panel never promises that a shared server has paused.

### Central interaction contract

[`interaction-state.ts`](../src/stichos/interaction-state.ts) is now the pure input-admission projection used by app controls and `window.stichos.state.interaction`. Its inputs retain independent owners: started/phase, paused/modal/transfer/dialogue/satchel, visibility/orientation, focus (`world`, `text`, `select`), pending (`idle`, `world`, `combat`) and placement (`none`, `estate`, `production`). It returns version 1, the effective surface, travel interruption and `simulate`, `move`, `travel`, `combat`, `interact`, `worldPointer`, `voice` capabilities with stable reasons and display messages.

- Text/select focus stops travel and held physical actions without freezing background life. Native focus release does not invalidate the input/select gesture ledger. A deliberate ground click may leave text entry.
- World acknowledgement temporarily pauses local simulation without discarding the route waiting at a door. Combat acknowledgement allows movement but prevents duplicate actions. Neither blocks native dialog navigation or Close.
- Placement permits manual approach and preview while denying ordinary combat and automatic travel. It is canceled at lifecycle boundaries rather than leaking to another world.
- Deliberate pointer PTT remains available while typing. The voice control independently excludes its V shortcut from text/select fields; focus changes release an already-held transmission. Capability never grants microphone consent.
- `strikeDestination` uses the authoritative underground kit; an unarmed surface appearance no longer redirects underground Strike to Gear. Domain range, cost, cooldown and authority checks still execute after admission.

This remains a projection over separate domain owners, not a global reducer. Typed modal, request and transfer owners now supply it; domain readiness still revalidates at the mutation boundary. See [closure decisions](LIFECYCLE-CLOSURE.md#additional-inventory-gaps).

## Convention for future changes: UX, DX and AX

1. **One canonical owner per fact.** Name its state fields, accepted events, guards, effects and reset boundary. Separate parallel dimensions such as output availability, connection readiness and worker cargo. Prefer a small union/transition helper over a global state-machine dependency.
2. **Every asynchronous operation settles.** Give it an owner/attempt token and explicit success, failure and cancellation paths. Ignoring stale callbacks is insufficient if the previous caller stays pending. Disposal releases timers, listeners, sockets, audio nodes and held input exactly once.
3. **Derive availability from canonical state.** Return stable reason codes plus readable messages, exact costs/container, cooldown/progress and target scope. UI and tests consume the same projection; mutation methods still revalidate. Do not parse English status text or use disabled styling as authorization.
4. **Preserve uncertainty and receipts.** A timed-out command may have committed. Reconcile the same identity rather than retrying under a new one, refunding optimistically or dropping a result because its panel closed. Make save/wire migration deliberate and separately tested.
5. **Make exits usable.** Close, Cancel, Stop and recovery remain reachable while unrelated requests are pending. Preserve native focus/IME/pointer semantics. Announce lifecycle changes and terminal results through a polite status region; do not announce every timer/frame. Associate disabled reasons with controls and retain warning geometry under reduced motion.
6. **Keep agent experience observational.** Extend versioned detached snapshots such as `state.interaction` with semantic target, authoritative scope, available action IDs, reason codes, bounded progress and last durable revision. Exclude tokens, recovery codes, private drafts and mutable engine references. Agents use the same visible/native commands and guards as people; diagnostics are not a new mutation backdoor.
7. **Test meaningful transitions.** Cover legal, rejected, canceled, duplicate, late, reload and ownership-change edges for the extracted owner. Cross-layer tests should assert actual outcome, cost, location and preserved identity—not only a label or a screenshot. Keep staged fixtures explicitly labeled; reserve browser claims for executed real-input routes.

The closure work follows these conventions through local transition owners and compatible projections. Keep future changes tied to this inventory and [the closure evidence](LIFECYCLE-CLOSURE.md); preserve the existing navigation, gesture, voice and receipt boundaries rather than replacing them with a global machine.
